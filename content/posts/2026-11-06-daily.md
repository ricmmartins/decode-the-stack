### [btoa() Is Lying to You: Base64, Unicode, and the Mojibake in Your JWT](https://dev.to/zhihu_wu_dea1d82af01a04d7/btoa-is-lying-to-you-base64-unicode-and-the-mojibake-in-your-jwt-bjd)
*An apparently successful encoding operation can conceal a mismatch between text and bytes.*

The article starts with a seemingly ordinary input: `café`. Its JavaScript example produces `Y2Fm6Q==`, then turns to Python to inspect the decoded bytes. The distinction is that `btoa()` operates on byte-valued input, while a JavaScript string is not itself a byte encoding. Getting a Base64 string back therefore does not establish that the text was represented as the receiving system expects.

Application teams should test the boundary between implementations, rather than only testing whether one implementation can reverse its own output. The title places the problem in a JWT context, but the supplied excerpt stops before showing the complete token example or proposed fix. It supports an interoperability warning, not a conclusion that a particular JWT library or authentication system is vulnerable.
